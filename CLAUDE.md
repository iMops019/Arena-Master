# Arena Master

A game built on C-Engine. The engine is the git submodule in `engine/` (repo: iMops019/C-Engine, a local working copy lives at `C:\Users\conov\Documents\C-Engine`).

## Rules

- **Never edit files under `engine/`.** Engine changes go in the engine repo: commit and push there, then run `./update-engine.ps1` here to move the submodule pointer and commit the bump. Anything game-specific stays out of the engine; the engine's `Instructions.md` explains the split.
- The game talks to the engine only through `IGameContent` (`engine/src/CEngine.Core/IGameContent.cs`) and the public `EngineWindow` API. `ArenaMasterContent` in `src/ArenaMaster.Game` is the implementation.
- Game assets go under this repo's `assets/` (`models/`, `textures/`, `sounds/`). The Editor's Save Terrain / Save Scene write `assets/terrain.dat` and `assets/scene.json` here. Raw Meshy exports go in the git-ignored `assets/raw/`; convert them with `engine/tools/asset-pipeline` and commit only the `.glb`.
- Engine architecture and conventions: `engine/CLAUDE.md` (large; search it rather than reading it all) and `engine/Instructions.md`.

## Status

The game is a 3D fantasy survivor-like (Megabonk-style), single player. **Read `DESIGN.md` first**: it has the design, the ground rules (nothing from ConnEngine-Game; one class at a time, starting with the Ranger; classes share nothing), the build order and the open questions. Build-order steps 1 to 3 are in. The user is happy with steps 1 (movement) and 2 (shooting and killing). Step 3 (levelling up) is waiting for them to try it.
- `ArenaMasterContent` builds a 512 m test map with hills, trees and rocks, turns on the engine's `ThirdPerson` view in Play mode, and runs everything below each frame. It also runs the level-up flow: kills drop gems, XP levels the player up, and each level sets the engine's `GamePaused` and shows `Ui/LevelUpScreen` (ImGui, drawn from `DrawOverlay`) until a pick is made. It draws the HUD: XP bar and level across the top, run clock, kills, HP, dash bar, damage numbers, and a "slain" screen that starts a fresh run after 3 s. The Play host sets `BuiltInPanels = false`.
- `Ranger/`: `RangerStats` (base numbers and the upgrades taken this run; everything reads from it), `RangerUpgrades` (the level-up pool and rolling 3 choices), `RangerController` (run, Shift dash, body faces the aim), `RangerBow` (auto-fires at whatever the crosshair is on, fanning split shots), and `RangerArrows` (straight flight, pierce, crits, sticking in the ground on a miss).
- `Combat/`: general, not tied to a class. `EnemyField` is a pure simulation: spawns in a ring 24-38 m from the player (kept at 14 alive), chases, keeps enemies apart, contact damage, hits and deaths. `EnemyView` draws each enemy as a placed prop with a bob, a flinch and a death sink. `EnemyKind.Ghoul` is the first enemy. Also here: `Experience` (level curve 5n), `XpGems` (gems, their magnet pull, and their view), `PlayerHealth` and `DamageNumbers`.
- Models are stand-ins generated by `tools/make_placeholder_models.py` (ranger, arrow, ghoul, xp gem). None are animated.
- Tests live in `tests/ArenaMaster.Game.Tests` (run `dotnet test ArenaMaster.slnx`). Keep simulation logic free of `EngineWindow` so it stays testable.

Don't open a visible game window without asking. Play mode grabs the mouse, and the user may be using the PC.
