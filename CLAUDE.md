# Arena Master

A game built on C-Engine. The engine is the git submodule in `engine/` (repo: iMops019/C-Engine, a local working copy lives at `C:\Users\conov\Documents\C-Engine`).

## Rules

- **Never edit files under `engine/`.** Engine changes go in the engine repo: commit and push there, then run `./update-engine.ps1` here to move the submodule pointer and commit the bump. Anything game-specific stays out of the engine; the engine's `Instructions.md` explains the split.
- The game talks to the engine only through `IGameContent` (`engine/src/CEngine.Core/IGameContent.cs`) and the public `EngineWindow` API. `ArenaMasterContent` in `src/ArenaMaster.Game` is the implementation.
- Game assets go under this repo's `assets/` (`models/`, `textures/`, `sounds/`). The Editor's Save Terrain / Save Scene write `assets/terrain.dat` and `assets/scene.json` here. Raw Meshy exports go in the git-ignored `assets/raw/`; convert them with `engine/tools/asset-pipeline` and commit only the `.glb`.
- Engine architecture and conventions: `engine/CLAUDE.md` (large; search it rather than reading it all) and `engine/Instructions.md`.

## Status

The game is a 3D fantasy survivor-like (Megabonk-style), single player. **Read `DESIGN.md` first**: it has the design, the ground rules (nothing from ConnEngine-Game; one class at a time, starting with the Ranger; classes share nothing), the build order and the open questions. Build-order steps 1 and 2 are in. Step 1 (third-person movement) feels good to the user. Step 2 (shooting and killing) is waiting for the user to try it.
- `ArenaMasterContent` builds a 512 m test map with hills, trees and rocks, turns on the engine's `ThirdPerson` view in Play mode, and runs everything below each frame. It also draws the HUD: HP bar, kill count, dash bar, damage numbers, and a "slain" screen that restarts the fight after 3 s.
- `Ranger/`: `RangerController` (7 m/s run, Shift dash, body faces the aim), `RangerBow` (auto-fires every 0.5 s at whatever the crosshair is on), and `RangerArrows` (straight-flying arrows that hit the first enemy on their path or stick in the ground).
- `Combat/`: general, not tied to a class. `EnemyField` is a pure simulation: spawns in a ring 24-38 m from the player (kept at 14 alive), chases, keeps enemies apart, contact damage, hits and deaths. `EnemyView` draws each enemy as a placed prop with a bob, a flinch and a death sink. `EnemyKind.Ghoul` is the first enemy. `PlayerHealth` and `DamageNumbers` are also here.
- Models are stand-ins generated by `tools/make_placeholder_models.py` (ranger, arrow, ghoul). None are animated.
- Tests live in `tests/ArenaMaster.Game.Tests` (run `dotnet test ArenaMaster.slnx`). Keep simulation logic free of `EngineWindow` so it stays testable.

Don't open a visible game window without asking. Play mode grabs the mouse, and the user may be using the PC.
